# Compact fold

Use the project's existing notebook or synthesis format. This is a guide, not a required report structure for every sketch.

```markdown
## <Date> — <central connection or outcome>

<What was learned and why it matters to the objective.>

- Evidence: <speculative, derived, tested or independently checked; links and scope>.
- Gain: <what the same rule/design now explains or improves; explicitly none if so>.
- Still supplied or uncertain: <inputs, assumptions, missing checks and deviations>.
- Decision: <keep, park, close within a stated scope, or revise exploratorily; reason>.
- Next question: <bounded question and why it beats the relevant alternatives>.

<Only if relevant: active owners/jobs, resource state, or a user decision.>
```

The user-facing update should convey the finding, uncertainty and next move in plain language. Link detailed evidence rather than reproducing the technical report. Do not equate task counts, passed checks or discarded sketches with progress toward an explanation.
